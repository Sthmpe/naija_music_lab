# Agent rules

Before substantive work read `README.md`, this file, `PROJECT_STATE.md`, `DECISIONS.md`, and the latest `SESSION_LOG.md` and `CHANGELOG.md` entries.

1. `PROJECT_STATE.md` is authoritative. Deep research is restricted to `CURRENT_ARTIST`. Directory existence grants no research authorization.
2. Begin with verified discography reconnaissance. Present project candidates and stop for user project approval. After approval, show complete selected-project track lists and standalone candidates, then stop for user song approval. The user has final selection authority.
3. Do not perform deep song analysis before both approvals. Analyse each approved song in `analysis.md` and `analysis.json` before project synthesis; finish all approved projects and singles before artist synthesis.
4. Record source URLs and access dates. Distinguish verified facts, estimates, interpretations and unknowns. Cross-check conflicting metadata and Nigerian language transcriptions. Never fabricate missing data.
5. Do not permanently store full copyrighted lyrics or distribute commercial audio. Use only brief excerpts necessary for analysis. Store original observations and metrics; keep research audio ignored by Git.
6. Audio analysis requires an authorized source or user file. If unavailable after reasonable search, set `AUDIO_STATUS: USER_FILE_REQUIRED`, list the missing input and continue non-audio work.
7. Separate song-specific, project-specific, possible, probable and repeated patterns. Do not generalize one song into an artist rule; do not populate `global/` heavily during the first artist.
8. Add new metrics as documented experiments. Record methodological or schema changes in `CHANGELOG.md` and major choices with reasons in `DECISIONS.md`.
9. Update `PROJECT_STATE.md` after every meaningful research task; append a concise `SESSION_LOG.md` entry. Do not rewrite prior log entries.
10. Extract transferable songwriting principles. Do not instruct generation systems to reproduce identifiable lyrics, melodies, catchphrases, or artist-specific combinations.
11. For Omah Lay, the complete user-approved corpus, including six collaborations, is locked at the top of `artists/01-omah-lay/selection.md`. Deep analysis is authorized. Across future artists, include `collaboration-behaviour.md` as an additional artist-level file using the standard template, and verify actual contribution before choosing feature cases.
